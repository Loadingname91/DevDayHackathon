Workbench Motion Lab

Quilter's Workbench in motion. Run each scenario on the phone, replay it, and switch on reduced motion to see the fallback. The beat sheet next to the phone shows what moves, when, and why.

Spool buddy: Clair's expressions

The spool is Clair's face. Each expression maps to one state in the stitch alphabet, so the face and the stitches always agree. On this sheet the one-time motions loop so you can see them; in the app, hop and shake play once.

Where it appearsOnly where Clair is acting (reading, building, asking for your OK) or the screen is empty. One spool per screen.
Where it never appearsTab switches, money warnings and dense lists. A sad face next to an overspend reads as judging.
Sizes30 px beside Clair's status line, 44 px on cards, 96 px in empty states and onboarding.

Build rules (optimize)

There is no app code yet, so this is a performance budget for the Next.js build. The prototype on this page follows it. Measure against it once the app runs.

  1. Tap answers within 100 ms. Stitching starts on tap (optimistic); the server confirms in the background. If it fails, the card frays, the threads pull back and it says "Couldn't save. Try again." Target INP under 200 ms.
  2. One focal animation at a time, 1.2 s max. The thread pull never overlaps another sequence; everything else is 220 ms or less.
  3. Only cheap properties. Threads are SVG stroke-dashoffset in an overlay with contain: paint; numbers roll with transform; patches move with FLIP. Never animate width, height, top or margins.
  4. The other device gets the tag, not the thread. When the phone stitches, the laptop updates numbers with the "just changed" tag only. The thread is for the person who acted.
  5. Zero raster images on home. Stitches and prints are CSS gradients; icons are one SVG sprite.
  6. Fonts: 3 families, 7 weights. Bricolage 700/800 (display only), Hanken 400/500/600, DM Mono 400/500, through next/font, Latin subset, font-display: swap.
  7. Many tabs are cheap; long tabs are not. 40 patches is about 250 DOM nodes, so no virtualization. Piles below the fold get content-visibility: auto. Virtualize a tab's rows past about 200.
  8. Measure: Lighthouse mobile with 4× CPU throttle on home and on the thread pull. LCP under 2.5 s, CLS under 0.1, no long tasks during the pull.
